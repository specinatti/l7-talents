1. Autenticação e Sessão

JWT com httpOnly Cookie Novo

O token de autenticação é armazenado em um cookie httpOnly; Secure; SameSite=Strict — completamente inacessível por JavaScript. Isso elimina o risco de roubo de token via XSS ou extensões maliciosas.

  • Token expira em 2 horas
  • Renovação automática a cada 90 minutos de uso ativo
  • Logout apaga o cookie no servidor (não apenas no browser)

Fingerprint de Sessão (IP + User-Agent) Novo

Cada token carrega o IP e o User-Agent do momento do login. Se o token for roubado e usado de outro dispositivo ou rede, o servidor rejeita automaticamente com "Sessão inválida".

Timeout de Inatividade

Sessão encerrada automaticamente após 30 minutos sem interação. Aviso aparece 2 minutos antes com opção de continuar.

Proteção contra Força Bruta

Rate limiting específico para login: máximo 20 tentativas por hora por IP. Após exceder, retorna HTTP 429 com tempo de espera.

2. Proteção de Dados

Senhas com bcrypt (salt rounds: 10)

Nenhuma senha é armazenada em texto puro. O algoritmo bcrypt é irreversível — mesmo com acesso ao banco, é impossível recuperar a senha original.

HTTPS Obrigatório em Produção Novo

Toda requisição HTTP é redirecionada automaticamente para HTTPS (301). Dados em trânsito sempre criptografados via TLS.

Dados de Pagamento — Nunca no Servidor

Dados de cartão são digitados diretamente em um iframe seguro do Mercado Pago (PCI DSS Level 1). O servidor L7 Talents nunca recebe número de cartão, CVV ou dados bancários.

Logs sem Dados Pessoais Novo

Logs do servidor não registram nome, email ou dados pessoais dos usuários — apenas eventos técnicos (erros, status HTTP, rotas).

Tentativa de acesso a role diferente retorna HTTP 403. Verificação feita no servidor — não apenas no frontend.

Prepared Statements (Anti SQL Injection)

Todas as queries ao banco usam parâmetros preparados ($1, $2...). Nenhuma query é construída por concatenação de strings.

Cache Busting Automático

Assets CSS/JS recebem ?v=timestamp a cada deploy. Páginas HTML têm Cache-Control: no-cache. Garante que usuários sempre recebem a versão mais recente.

4. Recuperação de Senha

  • Token gerado com crypto.randomBytes(32) — 256 bits de entropia
  • Expira em 1 hora e é invalidado após uso único
  • Endpoint não revela se o email existe (proteção contra enumeração de usuários)
  • Link de reset enviado por email (requer configuração SMTP)

6. Monitoramento e Resposta a Incidentes

Dashboard de Monitoramento em Tempo Real

Disponível em Dashboard Financeiro — atualiza a cada 60 segundos:

  • Status do servidor (uptime)
  • Latência do banco de dados
  • Uso de memória
  • Log dos últimos 20 erros
  • Candidaturas nas últimas 24h

Procedimento em caso de incidente

  1. Acesse railway.app → projeto l7-talents → Logs
  2. Identifique o erro nos logs do servidor
  3. Se suspeitar de comprometimento: altere o JWT_SECRET no Railway (invalida todas as sessões ativas)
  4. Notifique usuários afetados conforme LGPD (prazo: 72h para ANPD se dados sensíveis)
